NSLP HAL DMA Driver Documentation

What is NSLP?​

NSLP (Noordung Serial Link Protocol) is a communication driver for STM32 microcontrollers that lets multiple devices talk to each other over UART. Think of it like a postal service: each device has an address, packets have sender/receiver addresses, and NSLP handles delivery automatically using DMA (Direct Memory Access) for efficient, non-blocking communication.

Key Features:

  • Automatic packet framing and addressing
  • CRC error checking for reliable communication
  • Non-blocking transmission using DMA
  • Support for multiple UART instances
  • Simple callback-based reception

Quick Start Guide​

1. Configure Your Hardware (STM32CubeMX)​

Before writing code, configure these peripherals:

UART Settings:

  • Mode: Asynchronous
  • Baud Rate: Your choice (e.g., 115200)
  • Word Length: 8 Bits
  • Stop Bits: 1
  • Parity: None

DMA Settings (for your UART):

  • Add DMA Request for UART_TX: Mode = Normal, Priority = Medium
  • Add DMA Request for UART_RX: Mode = Normal, Priority = Medium

NVIC Settings:

  • Enable: UART global interrupt
  • Enable: DMA channel interrupts (for your UART's TX and RX)

CRC:

  • Enable CRC peripheral (default settings)

2. Initialize NSLP in Your Code​

#include "nslp_dma.h"

// Create an NSLP instance (one per UART)
nslp_instance_t my_nslp;

void setup(void) {
    // Initialize NSLP
    // Parameters: instance, UART handle, CRC handle, queue size, my address
    nslp_init(&my_nslp, &huart2, &hcrc, 8, 0x01);
    
    // Register callback for received packets
    nslp_set_rx_callback(&my_nslp, on_packet_received);
}

Parameter Explanation:

  • &my_nslp - Your NSLP instance variable
  • &huart2 - Which UART to use (huart1, huart2, etc.)
  • &hcrc - CRC peripheral handle (always &hcrc)
  • 8 - How many packets can wait in the send queue
  • 0x01 - This device's address (choose 0x01-0xFE, unique per device)

3. Add HAL Callbacks​

These three functions connect HAL interrupts to NSLP. Put them in your main.c:

void HAL_UART_TxCpltCallback(UART_HandleTypeDef *huart) {
    nslp_uart_tx_cplt_handler(huart);
}

void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t size) {
    nslp_uart_rx_event_handler(huart, size);
}

void HAL_UART_ErrorCallback(UART_HandleTypeDef *huart) {
    nslp_uart_error_handler(huart);
}

What these do:

  • First function: Called when sending completes → NSLP sends next packet in queue
  • Second function: Called when data arrives → NSLP validates and processes it
  • Third function: Called on errors → NSLP restarts reception

4. Send a Packet​

// Prepare your data
static uint8_t message[] = "Hello!";

// Create a packet
nslp_packet_t packet = {
    .receiver = 0x02,           // Send to device with address 0x02
    .type = 1,                  // Packet type (you define what types mean)
    .size = sizeof(message) - 1,// How many bytes to send
    .payload = message          // Pointer to your data
};

// Send it (non-blocking, returns immediately)
nslp_send_packet(&my_nslp, &packet);

Important: Use static or global variables for message buffers. The data must stay valid until transmission completes (happens in background via DMA).

5. Receive Packets​

Define a callback function that gets called automatically when packets arrive:

void on_packet_received(nslp_packet_t *pkt) {
    // This runs when a packet arrives (in interrupt context)
    
    printf("From: 0x%02X, Type: %u\n", pkt->sender, pkt->type);
    printf("Data: %.*s\n", pkt->size, pkt->payload);
    
    // Process based on packet type
    if (pkt->type == 1) {
        // Handle type 1 packets
    }
}

Important: This function runs in an interrupt, so keep it fast. Don't use delays or heavy processing here.

Understanding Packets​

Packet Structure​

When you send data, NSLP wraps it in a frame that looks like this:

┌────────────┬────────┬──────────┬──────┬──────┬─────────┬─────────┐
│ Start Byte │ Sender │ Receiver │ Type │ Size │ Payload │   CRC   │
├────────────┼────────┼──────────┼──────┼──────┼─────────┼─────────┤
│    0x7E    │ 1 byte │  1 byte  │1 byte│1 byte│ 0-255 B │ 4 bytes │
└────────────┴────────┴──────────┴──────┴──────┴─────────┴─────────┘

Field Details:

FieldWhat it isWho sets it
Start ByteAlways 0x7E, marks beginning of packetNSLP automatically
SenderAddress of device sending packetNSLP (from your init address)
ReceiverAddress of destination deviceYou set this
TypePacket type identifier (0-255)You set this
SizeHow many bytes in payload (0-255)You set this
PayloadYour actual dataYou provide this
CRCError checking codeNSLP calculates automatically

Total packet size: 9 bytes overhead + your payload (maximum 264 bytes total)

Packet Types​

The type field is for you to define. Some ideas:

#define MSG_TYPE_COMMAND    1
#define MSG_TYPE_DATA       2
#define MSG_TYPE_STATUS     3
#define MSG_TYPE_ACK        4

Then in your receive callback:

void on_packet_received(nslp_packet_t *pkt) {
    switch (pkt->type) {
        case MSG_TYPE_COMMAND:
            handle_command(pkt);
            break;
        case MSG_TYPE_DATA:
            handle_data(pkt);
            break;
        // etc...
    }
}

How NSLP Works Internally​

Sending Process​

┌─────────────────┐
│ You call:       │
│ nslp_send_pkt() │
└────────┬────────┘
         │
         ▼
┌─────────────────────────────┐
│ NSLP adds packet to queue   │
│ - Adds frame start (0x7E)   │
│ - Fills in sender address   │
│ - Calculates CRC            │
└────────┬────────────────────┘
         │
         ▼
┌─────────────────────────────┐
│ Is DMA currently sending?   │
├─────────────────────────────┤
│ NO → Start sending now      │
│ YES → Wait in queue         │
└────────┬────────────────────┘
         │
         ▼
┌─────────────────────────────┐
│ DMA sends packet over wire  │
│ (Your code continues        │
│  running, non-blocking)     │
└────────┬────────────────────┘
         │
         ▼
┌─────────────────────────────┐
│ When done, HAL calls:       │
│ HAL_UART_TxCpltCallback()   │
└────────┬────────────────────┘
         │
         ▼
┌─────────────────────────────┐
│ NSLP checks queue           │
│ - More packets? Send next   │
│ - Empty? Go idle            │
└─────────────────────────────┘

Key Point: nslp_send_packet() returns immediately. The actual sending happens in the background.

Receiving Process​

┌─────────────────────────────┐
│ DMA continuously listens    │
│ for incoming data           │
└────────┬────────────────────┘
         │
         ▼
┌─────────────────────────────┐
│ Data arrives!               │
│ HAL calls:                  │
│ HAL_UARTEx_RxEventCallback()│
└────────┬────────────────────┘
         │
         ▼
┌─────────────────────────────┐
│ NSLP validates packet:      │
│ - Check start byte (0x7E)   │
│ - Check receiver address    │
│ - Verify CRC                │
└────────┬────────────────────┘
         │
         ▼
┌─────────────────────────────┐
│ Valid packet?               │
├─────────────────────────────┤
│ YES → Call your callback    │
│ NO → Discard, restart       │
└────────┬────────────────────┘
         │
         ▼
┌─────────────────────────────┐
│ Your callback runs:         │
│ on_packet_received(pkt)     │
└─────────────────────────────┘

Key Point: Reception is automatic. You just define what to do when packets arrive.

API Reference​

Initialization​

nslp_init()​

void nslp_init(nslp_instance_t *inst, UART_HandleTypeDef *huart,
               CRC_HandleTypeDef *hcrc, uint16_t queue_length, 
               uint8_t address);

Purpose: Set up NSLP for use on a specific UART.

Call this: Once during startup, before sending or receiving.

Parameters:

  • inst - Your NSLP instance variable (declare as nslp_instance_t my_nslp;)
  • huart - UART to use (&huart1, &huart2, etc.)
  • hcrc - Always pass &hcrc
  • queue_length - How many packets can queue up (4-16 is typical)
  • address - This device's unique address (0x01-0xFE)

What happens:

  • Links NSLP to your UART
  • Allocates memory for buffers and queue
  • Starts DMA reception (begins listening immediately)
  • Stores your address for auto-filling sender field

Example:

nslp_instance_t node1;
nslp_init(&node1, &huart2, &hcrc, 8, 0x01);  // Node 0x01, queue of 8

Sending Packets​

nslp_send_packet()​

void nslp_send_packet(nslp_instance_t *inst, nslp_packet_t *packet);

Purpose: Send a packet to another device.

Call this: Anytime you want to send data.

Parameters:

  • inst - Your NSLP instance
  • packet - Packet structure with receiver, type, size, and payload

What happens:

  1. NSLP copies packet info to queue
  2. Adds frame start byte and sender address
  3. Calculates CRC
  4. If DMA is idle, starts sending immediately
  5. If DMA is busy, queues packet for later
  6. Function returns immediately (non-blocking)

Returns: Nothing (void) - check queue space before critical sends

Example:

static uint8_t data[] = "Test";
nslp_packet_t pkt = {
    .receiver = 0x02,
    .type = 1,
    .size = 4,
    .payload = data
};
nslp_send_packet(&my_nslp, &pkt);
// Function returns here, but packet is still being sent in background

Critical Notes:

  • Your data buffer must stay valid until transmission completes
  • Use static or global variables, not local variables
  • If queue is full, packet is silently dropped (check by monitoring)

Receiving Packets​

nslp_set_rx_callback()​

void nslp_set_rx_callback(nslp_instance_t *inst, 
                          void (*callback)(nslp_packet_t *));

Purpose: Tell NSLP what function to call when packets arrive.

Call this: Once after initialization.

Parameters:

  • inst - Your NSLP instance
  • callback - Your function that handles received packets

Your callback signature:

void your_function_name(nslp_packet_t *pkt) {
    // pkt->sender = who sent it
    // pkt->receiver = who it was sent to (your address)
    // pkt->type = packet type
    // pkt->size = data length
    // pkt->payload = pointer to data
}

Example:

void handle_incoming(nslp_packet_t *pkt) {
    printf("Got packet from 0x%02X\n", pkt->sender);
    // Process pkt->payload here
}

// Register it:
nslp_set_rx_callback(&my_nslp, handle_incoming);

Important: Your callback runs in interrupt context. Rules:

  • ✅ DO: Read packet data, set flags, copy data quickly
  • ❌ DON'T: Use HAL_Delay(), printf() to slow UART, heavy math
  • ❌ DON'T: Block or wait for anything

Best practice for heavy processing:

volatile uint8_t got_packet = 0;
nslp_packet_t saved_packet;

void handle_incoming(nslp_packet_t *pkt) {
    memcpy(&saved_packet, pkt, sizeof(nslp_packet_t));
    got_packet = 1;  // Set flag
}

void main_loop(void) {
    while (1) {
        if (got_packet) {
            got_packet = 0;
            // Now process saved_packet with all the time you need
            heavy_processing(&saved_packet);
        }
    }
}

Utility Functions​

nslp_min_delay()​

uint32_t nslp_min_delay(nslp_instance_t *inst);

Purpose: Estimate how long until all queued packets are sent.

Call this: When you need to know approximate transmission time.

Parameters:

  • inst - Your NSLP instance

Returns: Estimated milliseconds until queue is empty.

Calculation:

For each packet in queue:
  packet_bits = (packet_size_bytes × 10 bits/byte)
  packet_time_ms = (packet_bits × 1000) / baudrate
  total += packet_time_ms + 25ms overhead

Example:

// Send multiple packets
nslp_send_packet(&my_nslp, &pkt1);
nslp_send_packet(&my_nslp, &pkt2);
nslp_send_packet(&my_nslp, &pkt3);

// How long until all are sent?
uint32_t wait_time = nslp_min_delay(&my_nslp);
printf("Will take about %lu ms\n", wait_time);

Limitations:

  • Not precise - actual time varies with system load, interrupts
  • Estimate only - don't use for timing-critical operations
  • Doesn't include currently transmitting packet, only queued ones

When to use:

  • Rough timing for non-critical operations
  • Debugging queue status
  • User feedback ("Sending, please wait...")

When NOT to use:

  • Real-time control
  • Precise synchronization
  • Safety-critical timing

Status Flags​

nslp_rx_active (Global)​

extern volatile uint8_t nslp_rx_active;

What it is: Flag that shows if ANY NSLP instance is currently receiving.

Values:

  • 1 = Some instance is receiving data right now
  • 0 = All instances are idle

Use case:

if (!nslp_rx_active) {
    // Safe to do something that might interfere with all UARTs
}

inst->rx_active (Per Instance)​

if (my_nslp.rx_active) {
    // This specific UART is receiving
}

What it is: Flag showing if this specific instance is receiving.

Use case:

// Wait for this UART to finish receiving before sending
while (my_nslp.rx_active) {
    // Wait
}
nslp_send_packet(&my_nslp, &pkt);

HAL Callback Handlers​

These are internal functions called from your HAL callbacks. You don't call them directly.

nslp_uart_tx_cplt_handler()​

Called from: HAL_UART_TxCpltCallback()
When: DMA finishes sending a packet
What it does: Sends next queued packet or goes idle

nslp_uart_rx_event_handler()​

Called from: HAL_UARTEx_RxEventCallback()
When: Data is received
What it does: Validates packet, checks CRC, calls your callback

nslp_uart_error_handler()​

Called from: HAL_UART_ErrorCallback()
When: UART error occurs
What it does: Restarts reception, clears error flags

Complete Working Example​

Here's a full implementation showing proper setup:

#include "nslp_dma.h"
#include <stdio.h>
#include <string.h>

// ========================================
// 1. CREATE NSLP INSTANCE
// ========================================
nslp_instance_t nslp_node;

// Static buffer for sending (must persist)
static uint8_t tx_msg[64];

// ========================================
// 2. HAL CALLBACKS (REQUIRED)
// ========================================
void HAL_UART_TxCpltCallback(UART_HandleTypeDef *huart) {
    nslp_uart_tx_cplt_handler(huart);
}

void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t size) {
    nslp_uart_rx_event_handler(huart, size);
}

void HAL_UART_ErrorCallback(UART_HandleTypeDef *huart) {
    nslp_uart_error_handler(huart);
}

// ========================================
// 3. PACKET RECEIVE HANDLER
// ========================================
void on_packet_received(nslp_packet_t *pkt) {
    // This runs in interrupt context - keep it fast!
    
    printf("Received from 0x%02X: ", pkt->sender);
    printf("%.*s\n", pkt->size, pkt->payload);
    
    // Echo back what we received
    if (pkt->type == 1) {
        snprintf((char*)tx_msg, sizeof(tx_msg), 
                 "Echo: %.*s", pkt->size, pkt->payload);
        
        nslp_packet_t response = {
            .receiver = pkt->sender,
            .type = 2,
            .size = strlen((char*)tx_msg),
            .payload = tx_msg
        };
        
        nslp_send_packet(&nslp_node, &response);
    }
}

// ========================================
// 4. MAIN SETUP AND LOOP
// ========================================
int main(void) {
    // HAL initialization (generated by CubeMX)
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_USART2_UART_Init();  // Your UART
    MX_CRC_Init();
    MX_DMA_Init();
    
    // Initialize NSLP
    // This device will be Node 0x01
    nslp_init(&nslp_node, &huart2, &hcrc, 8, 0x01);
    
    // Register our receive callback
    nslp_set_rx_callback(&nslp_node, on_packet_received);
    
    printf("NSLP Node 0x01 Ready\n");
    
    // Send initial message to Node 0x02
    strcpy((char*)tx_msg, "Hello from Node 1!");
    nslp_packet_t hello = {
        .receiver = 0x02,
        .type = 1,
        .size = strlen((char*)tx_msg),
        .payload = tx_msg
    };
    nslp_send_packet(&nslp_node, &hello);
    
    // Main loop
    while (1) {
        // Your application code here
        // Packets are received automatically via callbacks
        
        HAL_Delay(1000);
    }
}

Common Patterns and Recipes​

Pattern 1: Request-Response Communication​

Node A (Sender):

static uint8_t request[] = "GET_STATUS";
nslp_packet_t req = {
    .receiver = 0x02,
    .type = MSG_REQUEST,
    .size = sizeof(request) - 1,
    .payload = request
};
nslp_send_packet(&nslp_a, &req);

Node B (Responder):

void on_packet_received(nslp_packet_t *pkt) {
    if (pkt->type == MSG_REQUEST) {
        static uint8_t response[] = "STATUS_OK";
        nslp_packet_t resp = {
            .receiver = pkt->sender,  // Reply to whoever asked
            .type = MSG_RESPONSE,
            .size = sizeof(response) - 1,
            .payload = response
        };
        nslp_send_packet(&nslp_b, &resp);
    }
}

Pattern 2: Broadcasting to All Nodes​

// Send to address 0xFF to reach all nodes
static uint8_t broadcast_msg[] = "ALERT!";
nslp_packet_t bcast = {
    .receiver = 0xFF,  // Broadcast address
    .type = MSG_BROADCAST,
    .size = sizeof(broadcast_msg) - 1,
    .payload = broadcast_msg
};
nslp_send_packet(&my_nslp, &bcast);

Note: Check the receive handler - it accepts packets for inst->address OR 0xFF.

Pattern 3: Sending Structures​

// Define your data structure
typedef struct {
    uint16_t sensor_id;
    float temperature;
    float humidity;
} SensorData;

// Send it
static SensorData data = {
    .sensor_id = 1,
    .temperature = 23.5,
    .humidity = 45.2
};

nslp_packet_t pkt = {
    .receiver = 0x02,
    .type = MSG_SENSOR_DATA,
    .size = sizeof(SensorData),
    .payload = (uint8_t*)&data
};
nslp_send_packet(&my_nslp, &pkt);

Receive it:

void on_packet_received(nslp_packet_t *pkt) {
    if (pkt->type == MSG_SENSOR_DATA) {
        SensorData *data = (SensorData*)pkt->payload;
        printf("Temp: %.1f, Humidity: %.1f\n", 
               data->temperature, data->humidity);
    }
}

Pattern 4: Multi-Instance (Multiple UARTs)​

nslp_instance_t nslp_uart1;  // For UART1
nslp_instance_t nslp_uart2;  // For UART2

void setup(void) {
    // Initialize both
    nslp_init(&nslp_uart1, &huart1, &hcrc, 8, 0x01);
    nslp_init(&nslp_uart2, &huart2, &hcrc, 8, 0x01);
    
    // Same callbacks work for both
    nslp_set_rx_callback(&nslp_uart1, on_packet_uart1);
    nslp_set_rx_callback(&nslp_uart2, on_packet_uart2);
}

The HAL callbacks automatically route to the correct instance.

Troubleshooting Guide​

Problem: No packets received​

Check:

  1. Are both devices using the same baud rate?
  2. Are TX of one connected to RX of the other?
  3. Is DMA enabled for RX in CubeMX?
  4. Did you call nslp_set_rx_callback()?
  5. Are UART interrupts enabled in NVIC?

Debug:

void on_packet_received(nslp_packet_t *pkt) {
    HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);  // LED blinks when packets arrive
    printf("Got packet!\n");
}

Problem: Packets corrupted or wrong data​

Check:

  1. CRC failures - check wire quality, baud rate mismatch
  2. Buffer size - is payload > 255 bytes?
  3. Buffer lifetime - did you use local variables for payload?

Fix:

// WRONG - local variable
void bad_send(void) {
    uint8_t msg[] = "Test";  // Dies when function returns!
    nslp_packet_t pkt = {.payload = msg, ...};
    nslp_send_packet(&my_nslp, &pkt);
}

// CORRECT - static variable
void good_send(void) {
    static uint8_t msg[] = "Test";  // Lives forever
    nslp_packet_t pkt = {.payload = msg, ...};
    nslp_send_packet(&my_nslp, &pkt);
}

Problem: Packets not sending​

Check:

  1. Is queue full? Default is 8 packets
  2. Is DMA enabled for TX in CubeMX?
  3. Did you implement HAL_UART_TxCpltCallback()?

Debug:

// Send packet and check if queue had space
nslp_send_packet(&my_nslp, &pkt);

// Estimate queue time
uint32_t delay = nslp_min_delay(&my_nslp);
if (delay > 1000) {
    printf("Warning: Queue is backed up!\n");
}

Problem: System hangs or crashes​

Check:

  1. Stack overflow - increase stack size in startup file
  2. Callback doing too much - move processing to main loop
  3. malloc failed - check heap size

Fix callback issues:

// BAD - too much work in interrupt
void on_packet_received(nslp_packet_t *pkt) {
    for (int i = 0; i < 1000000; i++) { /* heavy work */ }  // NO!
    HAL_Delay(100);  // NO!
}

// GOOD - quick flag and exit
volatile uint8_t process_flag = 0;
void on_packet_received(nslp_packet_t *pkt) {
    process_flag = 1;  // Quick!
}

Best Practices​

✅ DO:​

  • Use static or global variables for packet data buffers
  • Keep receive callbacks fast (< 1ms)
  • Initialize NSLP before sending any packets
  • Use unique addresses for each device (0x01, 0x02, 0x03...)
  • Define meaningful packet types (use #define constants)
  • Check baud rates match on all devices

❌ DON'T:​

  • Use local variables for packet payload
  • Call HAL_Delay() in receive callbacks
  • Send packets larger than 255 bytes
  • Forget to implement the three HAL callbacks
  • Use address 0x00 (reserved)
  • Send packets before calling nslp_init()

Advanced Topics​

Memory Usage​

Per NSLP instance:

  • RX buffer: 264 bytes (MAX_PACKET_SIZE)
  • TX buffer: 264 bytes
  • TX queue: queue_length × sizeof(pointer) bytes
  • Instance struct: ~60 bytes

Example: With queue_length=8, total ≈ 660 bytes per instance

Performance​

Transmission time example (115200 baud):

  • 10 byte packet: ~0.87 ms
  • 50 byte packet: ~4.3 ms
  • 255 byte packet: ~22 ms

Queue depth recommendations:

  • Simple nodes (status updates): 4-8 packets
  • Data loggers: 16-32 packets
  • Real-time control: 2-4 packets (low latency)

Multiple UARTs​

You can have multiple NSLP instances on different UARTs. The driver automatically routes callbacks to the correct instance:

nslp_instance_t nslp_uart1;
nslp_instance_t nslp_uart3;

nslp_init(&nslp_uart1, &huart1, &hcrc, 8, 0x01);
nslp_init(&nslp_uart3, &huart3, &hcrc, 8, 0x01);

// Same HAL callbacks handle both UARTs

Maximum instances: Defined by NSLP_MAX_INSTANCES (default: 4)

Summary​

To use NSLP:

  1. Configure UART + DMA + CRC in CubeMX
  2. Create instance: nslp_instance_t my_nslp;
  3. Initialize: nslp_init(&my_nslp, &huart2, &hcrc, 8, 0x01);
  4. Add three HAL callbacks (copy from example)
  5. Register receive handler: nslp_set_rx_callback(&my_nslp, my_handler);
  6. Send packets: nslp_send_packet(&my_nslp, &pkt);
  7. Receive automatically via callback

Key concepts:

  • Sending is non-blocking (happens in background)
  • Receiving is automatic (callback gets called)
  • Each device needs a unique address
  • Packet types are user-defined
  • CRC checking is automatic
